浏览器错误

ERR_CONNECTION_TIMED_OUT 怎么解决？逐步定位超时原因

Chrome 出现 ERR_CONNECTION_TIMED_OUT 时，先对比站点、网络与设备，再检查代理、DNS 与防火墙。

先确认：不同错误提示对应的排查方向不同。请保留浏览器显示的完整错误代码，避免同时修改多项设置。

这个错误意味着什么

浏览器等待连接或响应超过允许时间，无法仅凭它判断是 DNS、服务器忙碌还是中途网络丢包。

按顺序排查

  1. 记录失败是否稳定

    重新加载一次后等待；如果只有高峰期失败，可能与网站负载或链路拥塞有关。

  2. 确认其它站点与其它设备

    同设备不同站点正常，说明互联网连接不一定完全断开；多设备同站都失败时关注网站及共同网络。

  3. 关闭不必要的代理与安全拦截

    核对系统和浏览器代理设置；临时排除已知可信安全扩展，测试结束后恢复防护。

  4. 比较 Wi-Fi 与手机数据

    若移动网络能打开而 Wi-Fi 不行，检查路由器 DNS、网络认证与运营商线路。

进一步判断

如果只有一个网站长期超时，尝试查看网站官方状态公告；不要反复更改所有系统设置。对企业服务，可把发生时间和请求编号发给管理员。

浏览器错误含义也可参考 Google Chrome 官方帮助。

超时与网页返回错误不同

超时通常指连接过程未在规定时间内完成；它不等于网站返回了 HTTP 504。查看是否能解析出地址以及是否只有特定网络受影响，比反复刷新更有价值。

在 Chrome 开发者工具的“网络”面板中，可以查看请求是否根本没有建立连接。不要对不明来源网站执行所谓的“一键网络修复”脚本。

Windows 与 macOS 上的对比方法

Windows

打开“设置 → 网络和 Internet → 代理”查看是否有不认识的代理配置；在命令提示符运行 nslookup example.com（将域名替换为目标站点）。解析成功不代表网站一定可访问。

macOS

到“系统设置 → 网络 → 当前网络 → 详细信息”查看 DNS 与代理；终端中可运行 dig example.com。不要为了测试永久关闭防火墙。

观察结果

若只有某个站点超时，查看官方状态页；若 Wi-Fi 超时而热点正常，优先核对 Wi-Fi 网络路径。

连接超时不等于服务器已宕机

连接超时表示某个请求在限定时间内未完成。它可能发生在建立连接，也可能是页面某些资源等待太久。先确认错误出现在主页面还是某个资源；ping 不通也不能直接证明网站宕机，因为服务器可能主动忽略 ICMP。

如果只有办公 Wi-Fi 复现，记录网络条件后联系管理员；如果多条独立网络均在同一时间出现，可以查看网站状态页或联系站点支持。

超时并不等于 DNS 错误

DNS 查询可能已经成功，浏览器仍然可能在连接建立或等待服务器响应时超时。先记录能否解析，再比较同一域名在不同网络是否都超时；不要把一次 ping 不通视为服务器宕机，因为服务器可能禁用 ICMP。
