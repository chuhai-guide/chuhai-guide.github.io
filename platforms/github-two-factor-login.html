GitHub 双重验证无法登录、验证码不通过怎么办？

GitHub 能打开登录页，却卡在双重身份验证（2FA）环节，和网站连接失败不是一回事。先确定你还能使用哪种身份验证方式：验证器、通行密钥、安全密钥或此前保存的恢复码。

验证码一直提示错误

先确认输入的是当前 GitHub 账号对应的动态验证码，而不是另一个账号的六位数字。验证器生成的代码通常有短暂有效期，过期后应使用新代码。

检查手机的日期、时间与时区是否正确，建议开启自动设置。不要反复快速尝试过期代码，也不要向任何人发送验证码。

换手机或卸载验证器之后

查看是否仍有已登录的 GitHub 浏览器或其他可用验证方式；如果启用了安全密钥、通行密钥或其他第二因素，可以按 GitHub 登录界面提供的选项尝试。

如果曾经下载或打印恢复码，可以用未使用的恢复码完成恢复。恢复码属于敏感凭据，不能放在公共网盘、聊天截图或工单里。

恢复码也找不到怎么办

GitHub 的账号恢复可能受到已配置的验证方式和安全策略限制，并不保证一定能找回。应以 GitHub 官方登录和恢复页面当前提供的途径为准。

不要为了让登录界面继续而关闭浏览器安全保护、安装不明扩展或向所谓客服提供密码。登录界面能打开而 2FA 不通过，通常不应优先排查 DNS。

登录后尽快检查账户安全

恢复访问后，核对账号绑定邮箱、已有验证方式、恢复码是否仍安全，并补充可控的备用验证方法。

如果在公司组织内使用 GitHub，组织可能另有身份验证政策；遇到组织 SSO 限制时，应与组织管理员核对，不要当作个人账号密码错误。
