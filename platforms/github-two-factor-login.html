GitHub 双重验证无法登录、验证码不通过怎么办？

GitHub 能打开登录页，却卡在双重身份验证（2FA）环节，和网站连接失败不是一回事。先确定你还能使用哪种身份验证方式：验证器、通行密钥、安全密钥或此前保存的恢复码。

验证码一直提示错误

先确认输入的是当前 GitHub 账号对应的动态验证码，而不是另一个账号的六位数字。验证器生成的代码通常有短暂有效期，过期后应使用新代码。

检查手机的日期、时间与时区是否正确，建议开启自动设置。不要反复快速尝试过期代码，也不要向任何人发送验证码。

换手机后按现有验证方式逐项确认

  1. 仍有已登录设备：先保留该会话，在账号安全设置中查看已配置的验证方式；不要先退出唯一有效会话。
  2. 有安全密钥、通行密钥或备用验证方式：以 GitHub 当前登录页面显示的可用选项为准，不要假定每个账号都具备相同方式。
  3. 有未使用的恢复码：通过官方登录流程使用，完成后重新生成并妥善保管恢复码。
  4. 以上都没有：查看 GitHub 官方当前提供的账号恢复说明，确认能否符合条件；无法保证恢复成功。

恢复码、验证器代码与密钥都不能发送给自称客服的陌生人，也不要放进公开工单。

准备使用恢复码前，先核对自己是否保存了正确账号的恢复码；恢复码属于敏感凭据，不应上传到截图、在线客服聊天或公开仓库。登录成功后在安全设置中检查并更新恢复方式，避免下一次只剩唯一的验证设备。

全部恢复方式都不可用时

先检查是否保存过 github-recovery-codes.txt，以及登录页面是否显示已配置的其他恢复方式。GitHub 官方明确指出：如果丢失双重验证凭据且所有恢复方式均不可用，GitHub Support 不能为账号恢复访问。不要相信承诺通过客服绕过 2FA 的第三方。

部分账号可能符合邮件、已验证设备或密钥等恢复流程的条件，但这不是所有账号都能使用的通用后门；按 GitHub 官方恢复说明判断。

登录后尽快检查账户安全

恢复访问后，核对账号绑定邮箱、已有验证方式、恢复码是否仍安全，并补充可控的备用验证方法。

如果在公司组织内使用 GitHub，组织可能另有身份验证政策；遇到组织 SSO 限制时，应与组织管理员核对，不要当作个人账号密码错误。
